## Anti-Patterns Verdict

**Does this look AI-generated? No. Does it look finished? Also no.**

**LLM assessment.** The site does not commit the clichés it was warned about. No gradient hero, no hero metrics, no icon-heading-text card grid, no tracked-uppercase eyebrows, no 01/02/03 scaffolding, no glassmorphism. The `background-clip: text` gradient DESIGN.md flagged as "scheduled for removal" is genuinely gone — `.hero h1` computes to solid `#340014` / `#ffffff`. The berry ramp is real and it holds.

What it commits instead is **unowned vendor defaults in the trust-critical positions** — the "sterile default Starlight" anti-reference in its most damaging form. The visual system is two designs stacked: a hand-built berry theme wrapping three vendor components that a developer stares at more than anything else.

## Overall Impression

The words on this site are better than 90% of Gleam library docs, and the honesty is the actual differentiator — naming bravo and slate with links, conceding Mnesia does more, publishing a limitations page at all. A fluent BEAM developer would trust the prose and distrust the surface.

The single biggest opportunity is narrow and unusually tractable: **three vendor components carry the whole quality gap.** Code blocks, asides, and the mermaid diagram are the three things a developer looks at most on a library docs site, and all three ship untouched. Everything else — palette, type, contrast, layout discipline, copy — is already at or near the bar. This is not a redesign; it's a theming pass on three integration points.

## What's Working

1. **The honesty is real, and it's the product's differentiator.** `index.mdx:53-60` names bravo and slate with links and concedes Mnesia does more; `advanced/troubleshooting.md` answers "My ETS data disappeared after a crash — is the DETS file safe?" with "Yes… the DETS file on disk is a separate artifact and is left intact," then explains recovery. No other Gleam library site does this. It works because it inverts the reader's prior: a page that volunteers its ceiling is one you believe about its floor.

2. **The berry ramp holds AA everywhere, in both themes, with real margin — the risk DESIGN.md itself flagged did not materialize.** A full sweep of **708 visible text elements across 4 page/theme combinations returned 0 contrast failures.** Light body `#6b0031` on white 12.58:1; dark body `#f8aabe` on `#340014` 9.93:1; sidebar current 8.56:1; inline code 6.88:1. The narrowest margins on the entire site are syntax tokens at 5.49 (light) and 5.73 (dark) — both clear. Fonts resolve correctly too: `--sl-font-mono` genuinely lands on Spline Sans Mono Variable, loaded, no fallback. The Two-Ends Rule works.

3. **The splash resists every anti-reference it was warned about.** `<dl class="splash-features">` with no card chrome, no icons, no borders is a genuinely disciplined choice where most authors reach for a card grid. Plus `text-wrap: balance` on headings and `pretty` on paragraphs (`custom.css:16-22`), a detail almost nobody ships. And no page-level horizontal overflow at any tested width — the 1098px code blocks are correctly contained.

## Priority Issues

### [P1] Three vendor-default components break four named rules and one absolute ban
**What**: The table above. Code blocks are Night Owl in both themes; `.starlight-aside` carries a 4px `#f5bb3d` inline-start stripe with `border-radius: 0`; mermaid renders `#333333` Trebuchet MS on `#ececff`/`#9370db`. Not one berry value among them. Confirmed independently by the in-browser detector (`side-tab` on `aside.starlight-aside--caution`).
**Why it matters**: These are the three things a developer looks at most. DESIGN.md §5 says outright, "Code blocks are the site's most-read component; they must look deliberate in both themes." They currently look inherited. The 4px stripe is on the absolute-ban list with no exception. Note that the gray code tokens *pass* contrast — this is not an a11y failure, it's an identity failure, which makes it easy to leave undone forever.
**Fix**: (a) Define an Expressive Code theme from the ramp in `astro.config.mjs` — `expressiveCode: { themes: [berryDark, berryLight] }`, or at minimum `styleOverrides` mapping comment/keyword/string/function to `#ff729e` / `#e6bbcb` / `#f8aabe`. (b) In `custom.css`, override `--sl-color-asides-text-accent` and `--sl-color-asides-border` per type, replace the 4px inline-start border with a 1px hairline on all four sides plus one ramp step of background, and set `border-radius: 0.5rem`. (c) `mermaid({ mermaidConfig: { theme: 'base', fontFamily: '"Spline Sans Variable", sans-serif', themeVariables: { primaryColor: '#4d0022', primaryTextColor: '#f8aabe', lineColor: '#ab3772', primaryBorderColor: '#6b0031' } } })`.
**Suggested command**: `/impeccable colorize` (then `/impeccable polish`)

### [P1] Quick Start's first code block truncates the primary API call
**What**: `quick-start.mdx:16` puts the whole `set.open(...)` call on one 108-character line. At 390px the `<pre>` measures `clientWidth 356` / `scrollWidth 1098` — 68% of the line off-screen, and it's still cut at 1440px. Four of five blocks on `guides/write-modes.md` overflow too (742px / 482px / 692px of hidden content at 390px).
**Why it matters**: Completed quick-starts *are* the success metric in PRODUCT.md. The evaluator sees `set.open(name: "users", path: "data/users.dets", base_directory: "/app/data", ke` — cut mid-token — at the exact moment of maximum intent. *Downgraded from the design review's P0*: the copy button does exist and the block does scroll (no page-level overflow), so the task isn't blocked — but truncation with no edge-fade or persistent scrollbar reads as a broken page rather than a scrollable one.
**Fix**: Reformat the call across multiple lines exactly as `index.mdx:31-38` already does — the splash gets this right and the quick start doesn't. Add `expressiveCode: { defaultProps: { wrap: true } }` in `astro.config.mjs`, and audit every block over ~72 columns.
**Suggested command**: `/impeccable adapt`

### [P1] The architecture diagram is inaccessible, and it's the only explanation of the core mechanism
**What**: The mermaid SVG at `introduction.mdx:10-18` carries `role="graphics-document document"` and `aria-roledescription="block"` with **no `<title>`, no `aria-label`, no `desc`**. Screen-reader users get nothing from the section titled "How it works." It also renders 294px wide inside a 748px column, and disappears entirely with JS off.
**Why it matters**: WCAG AA is the stated target and this isn't decorative — it's the substance of the page reached by the splash's secondary CTA. It's the artifact answering "how does this actually work before I trust it with durable data," and it currently renders in Trebuchet MS with `#333333` text in lavender boxes.
**Fix**: Add `accTitle`/`accDescr` inside the mermaid source and put a two-sentence prose equivalent directly beneath the diagram — that serves screen readers, no-JS, and skimmers at once. Theme it per the issue above.
**Suggested command**: `/impeccable audit`

### [P2] Interaction states are browser defaults across the whole site
**What**: `a.sl-link-button.primary` and `a.site-title` compute `outline: 1px auto rgb(16,16,16)` with `box-shadow: none` — the UA default everywhere, never the accent. Both hero buttons compute `transition: all 0s`, so hover/focus snaps. At 390px, 11 undersized touch targets on `/` and 24 on `/guides/write-modes/`: hero CTAs are only **40px tall**, inline `bravo`/`slate` links are **19px**, and the **five code-block copy buttons are 32×32 with no accessible name at all**.
**Why it matters**: DESIGN.md §5 explicitly says "focus rings use the accent," and the product register requires 150–250ms transitions with full state coverage. The unnamed copy buttons are the sharper problem — they're the mobile escape hatch from the truncation issue above, and a screen-reader user can't find them.
**Fix**: In `custom.css`: `:focus-visible { outline: 2px solid var(--sl-color-accent); outline-offset: 3px; border-radius: inherit; }` and a `@media (prefers-reduced-motion: no-preference)` block giving links/buttons `transition: background-color 180ms ease, color 180ms ease, border-color 180ms ease`. Raise hero CTAs to 44px minimum. File or patch the missing accessible name on Expressive Code's copy button. Drop the 1px border on `.sl-link-button.secondary` — DESIGN.md §5 specifies "text-only with accent color; no fill, no border."
**Suggested command**: `/impeccable audit` (then `/impeccable animate` for the state transitions)

### [P2] `/introduction/` duplicates the splash and ships zero code
**What**: The page has no code at all. Its "Key features" list (`introduction.mdx:29-37`, 8 bullets) restates `index.mdx:64-100` (7 items) almost item-for-item; its "Why shelf?" restates "Compared to the alternatives" — and links bravo to a *different URL* than the splash does (`hex.pm/packages/bravo` vs `hexdocs.pm/bravo`).
**Why it matters**: This is the destination of the splash's secondary CTA — the page for the reader who wants more depth, and it gives them less: the same claims reformatted, without a single working line of Gleam. That directly violates "show the pattern, not the pitch." Duplication also reads as padding, which corrodes the honesty the rest of the copy earns.
**Fix**: Delete "Key features" outright. Open the page with the smallest complete `open → insert → lookup → close` example, keep (and theme) the diagram, and let the splash own the feature list. Reconcile the bravo URL.
**Suggested command**: `/impeccable distill`
