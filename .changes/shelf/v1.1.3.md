## v1.1.3 - 2026-11-17

#### Fixed

##### Preserve `fold` callback exceptions for all three table types. ([#109](https://github.com/tylerbutler/shelf/pull/109))

Callback exceptions propagate with their original Erlang class, reason, and stack trace, even if the callback closes the table. If you relied on conversion to `ShelfError`, handle expected failures in the callback or at your application's exception boundary. Closed-table traversal still returns `TableClosed`; `with_table` rescue behavior is unchanged.
##### Preserve POSIX file modes, owner, and group during `save()` and `close()`. ([#114](https://github.com/tylerbutler/shelf/pull/114))

If Shelf cannot preserve this metadata, the operation returns `FileError` before replacing the original file. Applications must handle this error, including when the process cannot restore the existing owner or group.

ACLs, extended attributes (including security labels), and file flags remain unsupported and can be lost during replacement.
##### Prevent concurrent opens within one VM through hard links and filesystem-supported case or Unicode aliases. ([#112](https://github.com/tylerbutler/shelf/pull/112))

A second open returns `NameConflict`, including during save. Opening now requires reliable device and nonzero inode values; otherwise it returns `FileError`. Use a filesystem that provides these values and trusted directories. Reservations do not provide cross-VM file locks.

Save replaces the file at the original path. Other hard links retain the old file and can then open as separate tables.
##### Reject DETS records that are not two-element key-value tuples on `open()` or `reload()`. ([#110](https://github.com/tylerbutler/shelf/pull/110))

Return `TypeMismatch` before decoding instead of discarding extra fields. A failed open preserves stored records; a failed reload leaves live ETS contents unchanged.

Use native DETS tools to migrate larger records to `#(key, value)` at a new path. Keep required extra fields inside the key or value, and retain the original file until you verify the migrated data.
##### Return `FileError` with native detail for a DETS table-kind mismatch. ([#108](https://github.com/tylerbutler/shelf/pull/108))

Handle an incompatible table kind as `FileError` and reopen with the file's original table kind. No data migration is needed. Decoder validation failures still return `TypeMismatch`.
